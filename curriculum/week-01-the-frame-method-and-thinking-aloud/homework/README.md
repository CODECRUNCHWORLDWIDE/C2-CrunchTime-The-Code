# Week 1 — Homework

Six problems. ~5 hours total. Each commits to your portfolio repo.

---

## Problem 1 — Set up your portfolio repo (45 min)

This is the mini-project's prerequisite. Get it done Thursday.

**Acceptance:**

- A public GitHub repo named `crunchtime-interview-prep-<yourhandle>` exists.
- It has a `README.md` cover, `.gitignore` (Python, macOS), and a `LICENSE` (CC-BY-4.0 or MIT — your choice for *your* work; C2 itself remains GPL-3.0).
- It has these directories: `frame-writeups/c2-week-01/`, `mocks/`, `system-design/`, `behavioral/`, `recruiter-prep/`, `study-plan/`, `badges/`.
- One initial commit.

See [mini-project/README.md](../mini-project/README.md) for the full spec.

## Problem 2 — Listen back to your Exercise 1 recording (30 min)

Take the recording you made for [Exercise 1 — Reverse the Siding](../exercises/exercise-01-reverse-the-siding.md).

**Acceptance:**

- A file `frame-writeups/c2-week-01/drill-01-self-review.md` in your portfolio repo containing:
  - Total recording length.
  - Three things you noticed about your own narration (fillers, pacing, structure, gaps).
  - One specific habit to drill in Exercise 2.

If listening back makes you cringe, that's data. Write it down.

---

## Problem 3 — FRAME on an unfamiliar problem (90 min)

Pick *one* problem you have never seen before, from anywhere — a free practice site, a textbook, a colleague. Easy or medium, and ideally two-pointer flavoured. **Do not** read anybody's solution before solving it. The point of this problem is that nothing about it is familiar, which is the one thing the rest of the week cannot give you.

**Acceptance:**

- Recording of your full FRAME solve, ≥15 minutes.
- FRAME write-up in `frame-writeups/c2-week-01/wild-01-<problem-slug>.md`.
- Tests passing (you write them).
- The write-up explicitly notes: how long did **Assess options** take? Did you name the right pattern, or did you start down one and have to back out?

The point of this is to test pattern recognition on an unfamiliar problem. If you only solve problems you've already heard of, you're not testing the skill.

---

## Problem 4 — Behavioral story #1 (45 min)

The course doesn't formally cover behavioral until Week 13, but we start the story bank early. Spaced repetition matters.

**Acceptance:**

- A file `behavioral/story-01.md` in your portfolio repo.
- Topic: **"Tell me about a time you debugged a hard problem."**
- Format: STAR (Situation, Task, Action, Result).
- 200–400 words total.
- Read it aloud at least twice. Note any sentences that didn't sound natural; rewrite them.

Don't have a great story yet? Use a small one. Behavioral practice is about *structure*, not heroism. Refining a small story is more valuable than telling a large one badly.

---

## Problem 5 — System-design ground zero (45 min)

We don't do real system design until Week 12. This is just a warm-up exposure.

**Acceptance:**

- A file `system-design/notes-week-01.md` containing a 300-word answer to: **"How would you sketch a system that shortens long URLs to short ones (like bit.ly)?"**
- Do not look up the canonical answer first. Write what you'd say in an interview today.
- After writing, search "URL shortener system design" and read one free article. Note three things you'd add to your answer next time.

---

## Problem 6 — Week 1 reflection (45 min)

A short reflection. 300–400 words at `study-plan/week-01-reflection.md`.

**Answer:**

1. What did FRAME feel like? Stilted? Natural? Useful? Annoying? Be honest.
2. Which of the five steps did you most want to skip, and what did skipping it cost you?
3. Which drill was hardest? Why?
4. Did pattern recognition speed up by Exercise 5 vs. Exercise 1?
5. What's one specific thing you'll do differently in Week 2?
