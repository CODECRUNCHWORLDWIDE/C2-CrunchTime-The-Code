# Exercise 1 — Build the Public Portfolio README

**Skill:** Curate the public portfolio (Lecture 1).
**Produces:** the README that is the front door of your portfolio repo.
**Target time:** 90 minutes.

## The task

Build the README for your public portfolio repository — the curated index of UMPIRE applied to 60+ problems across the 14 prior weeks. This is the single most-read file in your portfolio; a hiring manager forms their first impression here. By the end of this exercise you have a README that answers who/what/start-here above the fold and indexes every write-up by pattern.

This is not a hypothetical. Do it against your *real* `umpire-writeups/` folder. If your folder is missing write-ups (you skipped some weeks), note the gaps — back-filling them is the Monday homework — but build the README index around what you have and leave clearly-marked placeholders for the gaps.

## Specification

Your README must contain, in this order:

1. **Title + one-line pitch (above the fold).** Your name, then a blockquote with the one-line "what is this repo" pitch including the problem count.
2. **"Start here" (above the fold).** Three or four links to your flagship write-ups, chosen for *range* (one DP, one graph, one that shows communication, optionally a deep-dive).
3. **Index by pattern (below the fold).** A table, one row per pattern, each cell linking the write-ups for that pattern. Group by the 14 patterns, not by week.
4. **About this portfolio.** 2–3 sentences: what UMPIRE is, why every write-up follows it, what a reader should take away.
5. **Contact.** Professional email and LinkedIn link.

Use the [skeleton in resources.md](../01-resources.md#cheatsheet--the-portfolio-readme-skeleton) as a starting point.

## Acceptance criteria

- [ ] The who, the what, and the start-here all appear in the **first screenful** (roughly the first 15 rendered lines) — verify by previewing on GitHub.
- [ ] The one-line pitch states a **specific problem count** ("60+", or your real number). If yours is under 60, the homework back-fill closes the gap before you publish.
- [ ] The "start here" set has **3–4 links chosen for range**, not your three easiest problems.
- [ ] The index is grouped **by pattern**, every pattern row has **at least two links**, and the mock row is present.
- [ ] **Every link resolves** — click all of them after pushing. A broken "start here" link fails this exercise.
- [ ] The README contains **no private asides**, no "TODO," no emoji-soup, no "passionate ninja rockstar" language.
- [ ] The repo is **public** (or you have verified you can flip it public with no embarrassing commit messages or un-stripped asides in the history).

## Self-check

- Read only your own README's above-the-fold section. Could a stranger state, in one sentence each, who you are and what the repo is? If not, tighten it.
- Click your three "start here" links. Does each open a write-up that is genuinely among your best work? If one is weak, swap it.
- Count the patterns with only one entry. Each is a back-fill target for the homework.

## Why this exercise

The README is the four-minute experience condensed into thirty seconds. Get it right and a hiring manager gives you the four minutes; get it wrong and they close the tab. It is the highest-leverage single file you build this week, which is why it is Exercise 1 and why the resume (Exercise 2) and LinkedIn (Exercise 3) both link back to it.
